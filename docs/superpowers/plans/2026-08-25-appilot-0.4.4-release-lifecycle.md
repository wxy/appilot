# Appilot 0.4.4 发布生命周期与凭证降级实施计划

> **执行方式：inline（方式 2）**，不使用子代理；每任务独立 commit（前缀 `feat(0.4.4)` / `fix(0.4.4)` / `test(0.4.4)`），每轮验证后推送当前分支并开 PR。

**Goal:** 重构「GitHub 发布 → 文案 → ASC 版本」三者关系：文案身份改为 `appVersion`（一个版本一份文案，`releaseTag` 降级为内容来源）；版本状态与 GitHub 发布状态全部改为派生（废除本地 `storeStatus` 承担提交结果）；release 源升级为 GitHub Releases（发布草案可见）；缺少 GitHub/ASC 凭证时按可信度降级提供能力；所有依赖凭证出现的内容带来源徽章。

**已确认决策：**
- D1：文案身份 = `appVersion`；同版本新发布出现时重关联内容来源，不产生重复文案。
- D2：无 ASC 凭证 → iTunes lookup 粗粒度回退（`当前已上架` / `无法确认`）。
- D3：无 GitHub token → 公开仓库匿名读已发布 release；失败降级本地 git tags。
- 命名：**发布草案**（GitHub release draft）与**文案草案**（本地 copy draft）是两件事，UI 分开表述。
- 徽章：所有依赖凭证才出现的内容带来源徽章（GitHub / ASC / 商店公开查询 / 本地标签 / 未配置）。

## 概念模型

| 概念 | 权威来源 | 语义 | 是否有凭证依赖 |
|---|---|---|---|
| 发布草案 / 发布 | GitHub Releases API | 内容来源：这一版改了什么、是草案还是已发布 | GitHub token（Contents 只读；公开仓库已发布可匿名） |
| 文案（copy） | 用户本地操作 | 工作产物：文案是否生成、母本/整批是否确定；身份 = appVersion | 无 |
| 版本状态 | ASC（或 iTunes 公开查询降级） | 该版本是否提交 / 审核中 / 已上架 / 被拒 | ASC 凭证（降级时无需） |

**降级三档（UI 表达原则）：** 已确认（外部 API 直接给出）/ 推断（本地来源，如 git tag）/ 未知（缺凭证）。**绝不用否定词表达未知**（不显示「未上架」「未提交」来表示「不知道」）。

**状态不落库原则：** 版本状态、GitHub 发布状态一律派生（纯函数），不写回 draft 持久化字段；`storeStatus` / `githubDraftStatus` 保留字段兼容旧数据，但 UI 不再将其作为事实展示。

## Global Constraints

- 只读边界：外部平台全部只读（GitHub GET、ASC GET、iTunes 公开 lookup）；本地草稿、关键词跟踪集的写入不受限。
- engine 纯模块零 Electron 依赖；renderer 可 import engine 纯模块（现有先例）。
- 派生函数必须可单测、确定性；网络失败返回 null/[] 并走降级，不抛错中断流程。
- tsx 测试需沙箱外运行（IPC pipe 限制）；单测 `npx tsx tests/<name>.test.ts`，全量 `npm test`。
- 每个任务独立 commit；提交信息格式 `feat(0.4.4): <subject>` / `test(0.4.4): <subject>`。

### Task 1: 版本状态派生模块（TDD）

**Files:** Create `src/engine/version-status.ts`、`tests/version-status.test.ts`

接口：

```ts
export type VersionStatusSource = "asc" | "store-lookup" | "none";
export interface VersionStatus {
  key:
    | "not-in-asc"       // ASC 已拉到版本列表，但无 appVersion 匹配
    | "in-development"   // IN_DEVELOPMENT
    | "waiting-review"   // WAITING_FOR_REVIEW
    | "in-review"        // IN_REVIEW
    | "ready-for-sale"   // READY_FOR_SALE
    | "rejected"         // REJECTED / DEVELOPER_REJECTED
    | "store-live"       // 无 ASC，商店当前版本 == appVersion
    | "unknown";         // 无任何来源可确认
  label: string;
  tone: "muted" | "amber" | "emerald" | "red" | "blue";
  source: VersionStatusSource;
}

export function deriveVersionStatus(input: {
  appVersion: string;
  ascVersions?: { versionString: string; appStoreState?: string | null }[] | null;
  storeCurrentVersion?: string | null;
}): VersionStatus;
```

规则：
1. `appVersion` 为空 → `unknown`（无版本号可查）。
2. `ascVersions` 非空 → 按 `versionString === appVersion` 匹配：命中则按 `appStoreState` 映射（IN_DEVELOPMENT→开发中（未提交审核）、WAITING_FOR_REVIEW→等待审核、IN_REVIEW→审核中、READY_FOR_SALE→已上架、REJECTED/DEVELOPER_REJECTED→被拒）；未命中 → `not-in-asc`（label「ASC 未创建该版本」，source=asc，tone=amber）。
3. `ascVersions` 为 null（未配置/未拉到）且 `storeCurrentVersion === appVersion` → `store-live`（label「商店：当前已上架」，source=store-lookup）。
4. 其余 → `unknown`（label「未确认」，source=none；提示文案：配置 ASC 凭证后可查看提交/审核/上架状态）。

测试用例（≈16 条）：空版本、五类 ASC 状态、REJECTED/DEVELOPER_REJECTED、未命中 → not-in-asc、null ascVersions + 命中商店 → store-live、null + 不命中 → unknown、`ascVersions` 空数组按 not-in-asc 处理。

### Task 2: GitHub releases 读取 + 商店当前版本查询（TDD）

**Files:** Modify `src/engine/github-api.ts`、`src/engine/app-store-discovery.ts`；Create `tests/github-releases.test.ts`

`listGitHubReleases(localPath, token?, onStats?)`：
- `GET https://api.github.com/repos/{owner}/{repo}/releases?per_page=30`（`releases/tags/{tag}` 之外的新端点）。
- 解析 `tag_name / name / body / draft / prerelease / created_at / published_at / html_url`；按 `created_at` 倒序。
- 有 token：完整列表（含草案，需 push 权限）；无 token：匿名尝试（公开仓库返回已发布；草案不返回）。
- 网络失败/非 2xx/私有仓库 404 → 返回 `[]`（调用方降级），不抛错。

`fetchStoreCurrentVersion(trackId, country?)`：
- `https://itunes.apple.com/lookup?id={trackId}&country={country}`（默认 us）；复用 competitor-radar 的 lookup 解析模式。
- 返回 `{ version, currentVersionReleaseDate } | null`；失败返回 null。

测试：列表解析（含 draft=true 项、字段缺省容错）、Bearer 头、无 token 路径、非 2xx → []、lookup 解析、lookup 失败 → null。

### Task 3: release 源升级与降级（TDD）

**Files:** Modify `src/engine/release-watcher.ts`、`src/engine/store-submission.ts`；扩展 `tests/github-releases.test.ts`

- `ReleaseInfo` 扩展：`source: "git-tag" | "git-commits" | "release-draft-file" | "github-release"`；新增 `githubDraft: boolean | null`（null=未知/本地来源）。内部 `draft` 字段保留为「可生成文案的候选」语义（生成候选，不做 UI 展示用）。
- `checkForRelease` 增加 `githubReleases` 输入（由调用方传入 `listGitHubReleases` 结果）：非空时用其构建候选 release 列表（草案优先展示，按 created_at 倒序）；`tag = tag_name || \`gh-{releaseId}\``；`name` 取 release.name；`body` 优先 GitHub body；`publishedAt` 取 published_at || created_at；`githubDraft` 取真实值；`source="github-release"`。
- 无 `githubReleases`（无 token + 私有/失败）→ 现有 git tag 主分支路径；`githubDraft=null`、`source="git-tag"`。
- `inferAppVersion` 扩展：tag 非语义版本（如 `gh-123`）时，尝试从 release.name 提取语义版本；仍无 → 空（UI 提示用户填写目标版本）。
- 调度/手工入口接线：`release:list`、`release:context`、`release:get`、scheduler github-sync 均先调 `listGitHubReleases`，再走 `checkForRelease`。

测试：候选构建（草案置顶、字段映射、未打 tag 的 fallback tag）、有 token 与无 token 路径、失败降级到 git tag（githubDraft=null）、inferAppVersion 从 name 提取。

### Task 4: 文案身份归并（TDD）

**Files:** Modify `src/engine/store-submission.ts`、`src/main/project-state.ts`、`src/main/handlers/release.ts`；扩展 `tests/store-submission.test.ts`、`tests/release-format.test.ts`

- `store-submission.ts`：新增 `findDraftByVersion(project, productId, appVersion)`；注释明确 `releaseTag`=内容来源、`appVersion`=身份与 ASC 匹配键；`submissionDraftId` 保持不变（向后兼容存储键）。
- `project-state.ts` `upsertStoreSubmissionDraft`：写入前按 `(productId, appVersion)` 去重——存在同版本不同 id 的旧条目时移除旧条目（保留新写入实体）。
- `project-state.ts` 新增 `normalizeDraftIdentity(project)`：迁移函数，对现有 `storeSubmissionDrafts` 按 `(productId, appVersion)` 归并（保留 `updatedAt` 最新）；调用点：项目读取/`release:list` 前。
- `handlers/release.ts` `release:get`：existing 查找先 `findStoreSubmissionDraft(releaseTag)`，未命中再 `findDraftByVersion(appVersion)`；命中同版本不同来源时：
  - 非 force：返回现有内容，不改 `releaseTag`（不静默改来源）；
  - force 重新生成：将草稿 `releaseTag` 更新为新 release tag（重关联来源），内容重新生成，`masterConfirmedAt/batchConfirmedAt` 清空（内容变更后确认作废，符合现有 createStoreSubmissionDraft 行为）。
- `release:context` 的 `draftSummaries` 按 appVersion 去重返回；「当前文案/最新文案草案/历史文案」选择逻辑基于版本语义（当前=最新 batchConfirmedAt；草案=最新未确认）。

测试：去重保留最新、同版本重关联（force 更新来源+重置确认、非 force 不动）、迁移归并、`draftVersionLabel` 以 appVersion 优先（已有断言回归）。
