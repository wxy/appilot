>
> 日期：2026-09-14。

> 关联设计：[2026-09-14-post-release-promotion.md](./2026-09-14-post-release-promotion.md)

## 最新决策：X 优先的系列推广

本节覆盖下文与多平台首发、一次生成完整推广包有关的旧表述，旧内容保留作为决策历史。

- 正式渠道暂时只保留 X；Reddit 与 Facebook Group 降级为以后观察的辅助渠道，已有配置不删除。
- 一个上架版本对应一个 X 推广系列，而不是一条版本公告。
- 系统先生成 1–5 条互不重复的内容计划，再由用户按需要逐条生成、编辑和发布；小版本可以只有一条。
- 系列内容可以分别承担版本概览、功能点、真实使用场景和低营销感的交流问题，不生成 thread，也不要求连续发布。
- 每条内容同时生成英文 X 文案、英文场景图提示词和英文截图包装提示词；原始正式截图仍可直接发布。
- 场景图是完整、独立的实际使用画面，不含伪造 UI；截图包装图要求用户把真实截图作为附件交给生图模型，并保持截图完整、平直、可读，只设计外围环境。
- 用户显式保存手工修改；系统不得因自动保存循环阻断复制、展开提示词等操作。

## 1. 背景

Appilot 已经覆盖 Apple 应用的上架准备和上架后关键词排名跟踪，但两者之间缺少主动推广环节。

独立开发者完成版本上架后，通常仍需自行完成以下工作：

- 判断这次更新是否值得对外传播；
- 从大量版本变更中挑选普通用户真正关心的内容；
- 针对不同海外社交平台重新组织文案；
- 找到能够证明产品价值的真实截图；
- 制作或委托 AI 制作推广图片；
- 记住在哪个平台、何时完成了推广。

直接连接社交平台会引入 OAuth、平台审核、API 费用、规则变化和账号安全成本。首版不解决自动发帖，而是把发布工作台形成的可信版本事实转换成可直接执行的海外推广包。

现有截图成品生成在用户文件系统中，最终 PNG 路径没有作为长期业务记录保存，文件也可能被用户删除。推广功能必须让用户在推广时重新找到并选择一至两张截图，并将其导入 Appilot 自己管理的素材目录。

## 2. 产品目标

### 2.1 核心目标

让独立开发者在应用上架后，用尽可能少的判断和操作完成一次真实、可信、适合平台语境的海外推广。

用户不需要从零写文案，也不需要先配置任何社交平台或图片生成 API。

### 2.2 用户价值

- 从已确认的版本事实中自动找出最值得传播的价值；
- 允许系统诚实建议这次不值得推广；
- 一次形成统一推广角度，避免各平台说法互相矛盾；
- 获得 X、Reddit、Facebook 的平台原生文案；
- 获得可直接交给外部 AI 生图平台的提示词；
- 保存推广实际使用的截图和文案；
- 为未来产品生命线留下准确的推广事件。

### 2.3 产品成功定义

首版成功不是生成了多少内容，而是：

- 用户能在十分钟内从一个已上架版本得到可发布推广包，不含外部生图等待时间；
- 用户不需要从空白文本开始写作；
- 生成内容没有超出已确认发布事实；
- 用户能够找到、导入并长期保留真实截图；
- 至少一个推荐平台最终被用户标记为已发布；
- 后续可以准确回答某个版本在哪些平台、何时、使用什么内容完成了推广。

首批真实使用后再建立转化率基线，不在没有历史数据时设定虚假的增长百分比目标。

## 3. 非目标

首版不做：

- 修改或扩展发布工作台；
- 自动连接 X、Reddit 或 Facebook 账户；
- OAuth、自动发帖或定时发帖；
- 自动读取帖子 URL、浏览量、点赞、评论或关注变化；
- 为社交平台购买广告；
- LinkedIn、Threads、Mastodon 或国内平台；
- 普通版本的 Product Hunt 发布；
- Appilot 内直接调用 AI 图片 API；
- 自动生成最终宣传图片；
- 恢复旧趋势页面；
- 构建产品生命线页面；
- 声称推广导致下载量或排名变化。

## 4. 用户与使用前提

### 4.1 核心用户

主要用户是独立开发者或极小团队，同时承担开发、发布和产品运营。

典型特征：

- 有真实的 Apple 应用和本地代码仓库；
- 已经使用 Appilot 准备发布材料；
- 有 X、Reddit 或 Facebook 账户；
- 不愿意承担社交平台 API 的连接和维护成本；
- 可以手动在浏览器中完成最终发帖；
- 需要 AI 帮助判断和起草，但希望保留最终决定权。

### 4.2 使用前提

正式推广活动需要：

- 产品已经有可用的 App Store 链接；
- 目标版本已经上架；
- Appilot 能读取该版本的发布事实；
- 用户至少启用一个支持的平台；
- 用户愿意选择一至两张真实截图。

截图缺失不影响查看推广建议，但在默认流程中会阻止推广包进入已准备状态。

## 5. 信息架构

推广是项目级独立功能，位于发布和排名之间：

    总览
    副驾
    发布
    推广
    排名

推广模块包含两层：

1. 已上架版本及其推广状态列表；
2. 某个版本的推广活动详情。

不在推广模块中再次展示发布工作台的完整流程，也不把排名图表嵌入首版推广详情。

## 6. 核心概念

### 6.1 推广活动

一个产品的一个已上架版本最多对应一份权威推广活动。

活动可以经历：

    待判断 → 草稿 → 已准备 → 部分已发布 → 已完成
                  └→ 已跳过

### 6.2 推广建议

系统将版本分为：

- 强推广：有明显新价值，适合多个平台；
- 轻量更新：适合一次简短更新；
- 建议跳过：没有足够的用户可感知价值。

### 6.3 核心推广简报

所有平台共用的一份权威表达，包括：

- 目标受众；
- 用户问题；
- 主传播角度；
- 核心价值；
- 事实证据；
- 行动号召；
- 禁止声称的内容；
- 视觉方向。

### 6.4 平台交付项

一次活动可以有多个平台交付项。每个交付项保存自己的文案修订、目标表面、实际使用素材和发布时间。

### 6.5 受管推广素材

用户从文件系统选择截图后，Appilot 验证并复制一份到自己的受管目录。后续推广不再依赖原文件。

## 7. 产品级推广设置

用户第一次进入某个产品的推广模块时，完成一次轻量设置。

### 7.1 平台启用

可启用：

- X；
- Reddit；
- Facebook。

默认行为：

- X 可以直接启用；
- Reddit 没有目标社区时显示待配置；
- Facebook 没有目标表面时显示待配置。

### 7.2 Reddit 设置

用户添加一个或多个目标 subreddit：

- 社区名称；
- 可选的受众备注；
- 可选的发帖注意事项。

Appilot 不自动认定某个社区适合产品，也不把历史备注当作当前社区规则。每次准备发帖时仍提示检查社区规则。

### 7.3 Facebook 设置

用户为产品添加一个或多个目标表面：

- 产品 Page；
- 具体 Group；
- 个人动态。

每个目标表面可以保存受众备注和发帖注意事项。

### 7.4 不保存账号凭据

产品级推广设置不要求登录，不保存密码、Cookie、Token 或浏览器会话。

## 8. 推广首页

### 8.1 页面目标

让用户快速知道：

- 哪些已上架版本还没有处理推广；
- 哪些版本正在准备；
- 哪些平台已经发布；
- 哪些版本被建议跳过。

### 8.2 版本条目

每个条目显示：

- 版本号；
- 上架日期；
- 推广建议；
- 当前活动状态；
- 平台完成情况；
- 最近更新时间；
- 一个与当前状态一致的主操作。

示例：

    v1.3.0 · 强推广 · 2/3 已发布
    v1.2.9 · 轻量更新 · 已完成
    v1.2.8 · 建议跳过

### 8.3 排序

- 最新上架版本优先；
- 未处理和处理中版本优先于已完成历史；
- 同一版本不重复出现。

### 8.4 空状态

没有已上架版本：

> 尚无可推广的已上架版本。完成一次上架后，Appilot 会在这里准备推广建议。

版本存在但平台未配置：

> 先选择这个产品用于海外推广的平台。

## 9. 创建推广活动

### 9.1 触发

用户选择未处理版本后，Appilot 读取发布模块形成的版本事实并创建来源快照。

不因进入页面而自动调用 AI。用户明确点击分析后才开始。

### 9.2 分析输出

系统先通过一次较短的 AI 请求生成：

- 推广建议等级；
- 简短理由；
- 一个推荐主角度；
- 推荐平台组合；
- 推荐寻找的截图类型。

页面先展示判断，不立即铺开所有平台文案。

此阶段不生成平台全文和图片提示词。若建议为“不推广”，用户可以直接结束，避免先寻找素材以及承担完整生成成本。

### 9.3 用户决策

用户可以：

- 接受建议并继续；
- 调整本次启用的平台；
- 修改或要求重做主角度；
- 标记本次跳过。

标记跳过需要保存原因和时间，但不要求用户填写长文本。

## 10. 截图选择

### 10.1 推荐截图

Appilot 根据发布阶段已经确认的截图类型和主传播角度，推荐一至两个截图名称。

示例：

> 建议选择 Dashboard Overview 和 Token Cost Breakdown。

推荐名称只是寻找线索，不代表 Appilot 已经持有最终 PNG。

### 10.2 寻找提示

页面说明：

> 发布截图通常保存在 Keynote 模板旁、以产品名和版本号命名的 screenshots 文件夹中。文件可能已被移动或删除，请选择当前实际存在的图片。

如果仍有 Keynote 模板路径：

- 文件选择器默认从模板所在目录开始；
- 可以提供在 Finder 中打开该目录；
- 不声称推断出的截图目录一定存在。

### 10.3 选择规则

- 一次最多选择两张；
- 至少选择一张才能进入默认的已准备状态；
- 支持多选；
- 文件必须可以本地解码；
- 选择后展示预览、文件名和尺寸；
- 用户可以替换、移除或调整主次顺序；
- 第一张默认为主截图，第二张为辅助截图。

### 10.4 导入行为

用户确认后，Appilot：

1. 验证文件；
2. 计算 SHA-256；
3. 复制到受管推广素材目录；
4. 保存素材元数据；
5. 从此使用受管副本。

界面使用“导入截图”，避免让用户误以为只是创建书签。

### 10.5 删除和缺失

- 删除外部原文件不影响已导入素材；
- 删除活动前必须说明受管素材是否仍被引用；
- 受管副本意外缺失时，明确显示缺失，不静默读取原始路径；
- 用户重新导入相同内容时通过哈希识别；
- Appilot 不移动、修改或删除用户原文件。

## 11. 生成推广包

### 11.1 生成条件

生成按钮需要：

- 推广建议已确认；
- 至少一个平台可用；
- Reddit 和 Facebook 已具备各自目标上下文；
- 至少导入一张真实截图；
- 来源版本仍然有效。

### 11.2 完整推广包生成

用户确认传播角度并导入截图后，发起流程中的第二次 AI 请求，以一次结构化生成产生：

- 核心推广简报；
- 已启用平台的文案；
- 共用视觉简报；
- 各平台图片提示词变体。

AI 运行期间显示：

- 正在整理核心推广简报；
- 正在适配平台内容；
- 正在生成图片提示词；
- 已接收字符数或其他真实进度；
- 停止按钮。

不能使用伪进度百分比。

### 11.3 事实边界

每条功能、数字和效果主张必须来自冻结的版本事实。

不得：

- 把计划中的功能写成已经发布；
- 推断没有证据的用户规模、下载增长或性能提升；
- 根据截图视觉猜测功能；
- 伪造评分、奖项、媒体评价或 App Store 徽章；
- 为了营销效果扩大技术事实。

无法证实的表达应被删除，而不是使用模糊措辞掩盖。

## 12. 核心推广简报体验

平台内容上方显示活动级核心简报：

- 推荐受众；
- 用户问题；
- 主传播角度；
- 一句话价值；
- 主要证据；
- 行动号召；
- 不应声称什么。

用户可以修改主传播角度。修改后，系统明确提示平台文案已经过时，需要由用户决定是否重新适配。

系统不能在后台静默重写已经编辑的文案。

## 13. 图片提示词体验

### 13.1 输出内容

每个平台显示：

- 建议使用的截图；
- 需要上传到外部平台的图片顺序；
- 平台画面比例和裁切说明；
- 一键复制的完整提示词；
- 一键复制的负面提示词；
- “参考图合成”和“只生成背景”两种模式。

### 13.2 默认推荐

默认推荐“只生成背景”：

1. 用户把背景提示词交给外部 AI；
2. AI 只生成背景、光线和装饰；
3. 用户在外部工具或以后由 Appilot 叠加真实截图。

这是因为图片模型即使收到保持不变的指令，也可能重绘截图 UI、文字和数字。

### 13.3 参考图合成

参考图合成模式明确列出：

    图片 1：主截图，必须保持 UI 不变
    图片 2：辅助截图，可缩小或部分遮挡
    图片 3：App 图标，如可用

提示词包含：

- 推广目标；
- 目标受众；
- 主视觉概念；
- 构图；
- 背景和光线；
- 品牌色；
- 留白和裁切安全区；
- 后期标题位置；
- 必须保持的真实元素；
- 禁止生成的元素。

页面同时提示：

> 外部图片模型可能修改参考截图。发布前请检查界面、文字、数字和产品功能是否真实。

### 13.4 导入外部成品

用户在外部平台生成图片后，可以选择“导入成品”：

- 选择图片；
- 预览；
- 复制到活动受管目录；
- 记录为外部生成成品；
- 选择它用于一个或多个平台。

首版不要求记录外部生成平台名称或费用。

## 14. X 交付项

### 14.1 输出

- 一条标准长度主帖；
- 一个备用开头；
- App Store 链接；
- 建议图片；
- 图片提示词；
- 字符校验。

### 14.2 行为

- 主帖可编辑；
- 实时显示长度；
- 链接按平台当前确定性规则计算；
- 支持复制文案；
- 支持在 Finder 中显示选定图片；
- 支持打开 X；
- 支持标记已发布。

### 14.3 Thread

只有强推广或用户明确要求时才生成 Thread。普通更新不默认制造多条内容。

## 15. Reddit 交付项

### 15.1 前提

必须选择一个产品级目标 subreddit。没有目标社区时，页面先要求配置，不生成所谓通用 Reddit 文案。

### 15.2 输出

- 目标社区；
- 适合该社区的理由；
- 标题；
- 正文；
- 开发者身份披露；
- 链接放置建议；
- 建议图片；
- 图片提示词；
- 发帖前规则检查提示。

### 15.3 内容原则

- 以问题、经验、使用场景或真实开发过程为中心；
- 明确说明开发者身份；
- 不伪装成第三方用户推荐；
- 不把 X 文案机械扩写；
- 不承诺帖子符合社区当前规则；
- 不生成求赞、诱导互动或规避审核内容。

## 16. Facebook 交付项

### 16.1 前提

必须选择一个目标表面：

- 产品 Page；
- 具体 Group；
- 个人动态。

如果没有明确受众，AI 可以建议本次跳过 Facebook。

### 16.2 输出

- 面向目标受众的正文；
- App Store 链接；
- 推荐的一至两张图片；
- 图片提示词；
- Group 场景下的规则检查提示。

### 16.3 内容原则

- 可以比 X 更完整地交代场景和价值；
- 允许复用核心视觉；
- 不直接复制 X 短帖；
- 不假定普通账户天然具有产品分发能力。

## 17. 编辑、保存与重新生成

### 17.1 自动保存

用户编辑文案时自动保存草稿，并明确显示保存状态。

### 17.2 单平台重新生成

用户只能重做当前平台，不能因为重做 X 而覆盖 Reddit 或 Facebook。

重新生成发送：

- 完整版本事实；
- 已确认核心简报；
- 导入素材的角色和元数据；
- 当前平台文案；
- 用户反馈。

### 17.3 修订保护

- 手工编辑内容不被后台刷新覆盖；
- 重新生成先形成新修订；
- 用户确认替换后才成为当前稿；
- 已发布修订保持只读历史；
- 不能修改历史后让它看起来像当时实际发布的内容。

## 18. 发布操作与状态

### 18.1 首版操作

- 复制文案；
- 复制图片提示词；
- 在 Finder 中显示素材；
- 打开平台；
- 标记已发布。

### 18.2 标记已发布

用户点击后：

- 记录平台；
- 记录发生时间；
- 记录实际使用的文案修订；
- 记录实际选择的素材；
- 交付项进入已发布。

这只是用户确认，不是平台回执。界面不得显示“已由平台验证”。

### 18.3 撤销误标记

允许撤销误操作，但保留一次审计记录。撤销后交付项返回已准备。

### 18.4 活动完成

- 一个或多个平台发布、其余仍待处理：部分已发布；
- 所有未跳过平台均发布：已完成；
- 用户明确跳过整个版本：已跳过。

## 19. 错误和边界状态

### 19.1 发布事实不可用

> 无法读取这个版本的最终发布材料。请先确认版本已经上架。

不创建不完整的正式活动。

### 19.2 截图找不到

显示推荐截图名称和寻找说明，允许重新打开文件选择器，不把旧输出路径显示成仍然存在。

### 19.3 图片无法导入

保留原活动状态，说明是文件缺失、格式不可读、复制失败还是空间不足。已经成功导入的另一张图片不能回滚丢失。

### 19.4 AI 生成失败

- 保留素材和用户设置；
- 显示真实错误；
- 允许重试；
- 用户停止后不自动重启；
- 已有平台文案不因失败被清空。

### 19.5 平台目标缺失

- Reddit 缺少 subreddit：只阻塞 Reddit；
- Facebook 缺少目标表面：只阻塞 Facebook；
- X 可继续生成；
- 活动页面明确显示每个平台为何不可用。

### 19.6 来源版本发生变化

如果已上架版本事实被重新同步并变化：

- 已发布活动不改写；
- 未发布活动提示来源有更新；
- 用户决定保持当前来源或重新建立来源快照；
- 重新建立来源快照后，现有平台稿标记为可能过时。

## 20. 隐私、安全与成本

- 首版不上传截图到 Appilot 之外，除非用户主动把它交给外部 AI 平台；
- 选择外部平台时明确由用户负责该平台的数据条款；
- 原文件只读；
- 导入使用复制，不使用移动；
- 受管素材不写入用户项目仓库；
- 不保存社交平台凭据；
- 不自动打开或发送内容；
- 不自动调用可能产生费用的图片 API；
- 删除活动或素材前检查引用关系并明确影响。

## 21. 产品生命线预留

首版只记录稳定的推广发布事件：

- 产品；
- 版本；
- 平台；
- 推广角度；
- 文案修订；
- 素材；
- 用户确认的发布时间。

不实现：

- 时间线页面；
- 下载量曲线；
- 推广前后排名比较；
- 渠道归因；
- AI 效果结论。

未来产品生命线可以读取这些事件，但只能表达时间相关性，不能把推广自动解释为下载或排名变化的原因。

## 22. 成功指标

### 22.1 MVP 可用性

- 从选择已上架版本到推广包已准备，不超过十分钟，不含外部生图时间；
- 用户不从空白文案开始；
- 用户核心决策不超过推广建议、主角度和截图选择；
- 选择截图后，原文件删除不影响活动；
- 一个活动可以完成至少一个平台的发布记录。

### 22.2 内容质量

- 所有产品主张可追溯到版本事实；
- Reddit 内容明确开发者身份；
- 各平台内容不是同一文本的机械裁剪；
- 图片提示词明确引用真实素材；
- 不把图片模型生成结果视为天然可信。

### 22.3 真实使用观察

首批至少以两个真实上架版本验证：

- 一次强推广或轻量推广；
- 至少一次 X 发布；
- 至少一次 Reddit 或 Facebook 发布；
- 一次外部图片提示词使用和成品导入；
- 一次原截图删除后的受管副本验证；
- 一次单平台重新生成且不影响其他平台。

## 23. MVP 验收标准

- 推广作为独立项目模块出现，不进入发布工作台；
- 只列出已上架版本；
- 首版只支持 X、Reddit、Facebook；
- AI 可以建议强推广、轻量更新或跳过；
- 用户可以确认一个活动级主传播角度；
- Reddit 必须选择具体 subreddit；
- Facebook 必须选择 Page、Group 或个人动态；
- 用户可选择一至两张截图；
- 选择后图片复制到 Appilot 受管目录并记录哈希；
- 删除外部原文件后仍可预览和使用受管素材；
- 价值分析与完整推广包生成是两次目的不同的 AI 请求；
- 完整推广包请求一次产生核心简报、平台文案和视觉简报；
- 每个平台提供可复制的外部生图提示词；
- 提示词列明参考图片和禁止事项；
- 外部生成成品可以重新导入并被平台选用；
- 单平台重做不覆盖其他平台；
- 用户可以复制内容、打开平台并标记已发布；
- 已发布事件记录版本、平台、修订、素材和时间；
- 首版不要求社交平台或图片 API Key；
- 页面不暗示已经自动发帖或验证平台结果；
- 不实现旧趋势或产品生命线。

## 24. 分期

### P0：数据和素材基础

- 产品级推广设置；
- 推广活动、平台交付项和修订；
- 发布事实快照；
- 素材选择、校验、哈希、复制和缺失处理；
- 推广发布事件。

### P1：首版完整流程

- 独立推广页面；
- 推广价值判断；
- 主角度确认；
- X、Reddit、Facebook 文案；
- 图片提示词；
- 编辑、复制、打开平台；
- 标记已发布。

### P2：外部图片成品

- 导入外部生成图片；
- 平台选择实际使用的图片；
- 单平台重做和修订保护；
- 素材清理和审计完善。

### P3：可选图片 API

- 独立 ImageProvider；
- 用户自己的 API Key；
- 费用预估和实际用量；
- 参考图片输入；
- 生成结果自动导入；
- 取消、失败和重复计费保护。

### P4：Product Hunt

- 仅首发或重大更新；
- 独立 Launch Kit；
- 不混入普通 Release 推广完成条件。

产品生命线需等待推广事件和真实下载数据积累后另立 PRD。

## 25. 依赖

- 发布模块能够稳定识别已上架版本；
- 能读取版本最终事实和 App Store 链接；
- 截图文案仍能提供截图类型名称；
- 本地数据库可以保存活动、修订、素材元数据和推广事件；
- Appilot 应用数据目录具备稳定的素材存储和备份边界；
- 现有 AI 请求支持结构化 JSON、取消和使用量记录。

## 26. 尚未决定但不阻塞 MVP 的事项

- 受管推广素材是否纳入统一导出和备份；
- App 图标的可靠读取来源；
- X、Reddit、Facebook 平台规则的更新机制；
- 首个图片 API 供应商；
- 是否加入本地确定性宣传图合成器；
- Product Hunt 首次用于哪个产品；
- 产品生命线的数据源、页面位置和信息架构。

## 27. 发布门槛

在宣称推广 MVP 完成前，必须用真实产品完成一次端到端验收：

1. 读取一个真实已上架版本；
2. 得到可解释的推广建议；
3. 选择并导入真实截图；
4. 删除或移动原截图后确认受管副本仍然可用；
5. 生成三个平台中的至少两个；
6. 使用一次外部生图提示词；
7. 导入外部生成成品；
8. 手工完成至少一个真实平台发帖；
9. 标记已发布并重新读取活动；
10. 证明保存的版本、文案修订、素材和时间一致。

代码测试通过不替代这项真实使用验收。
